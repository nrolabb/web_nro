# Vá bảo mật Web NRO — 29/10/2026

Đã triển khai các bản vá trong mã và môi trường cục bộ của `D:\NRO\NROKHACH\Web NRO\Web`. Không ghi bí mật vào báo cáo.

## Đã vá

- **JWT:** xóa khóa cố định khỏi source; tạo khóa ngẫu nhiên riêng trong `.env`; ứng dụng từ chối khởi động nếu thiếu khóa đủ dài. Token chỉ nhận HS256, issuer/audience cố định, phải có subject là account ID và thời hạn 7 ngày. Đã xoay khóa cục bộ, vì vậy các phiên web cũ hết hiệu lực. Login không còn trả token trong JSON.
- **DB:** tạo user MySQL `nro_web_runtime` với quyền SELECT/INSERT/UPDATE/DELETE chỉ trên database cấu hình; đổi `DB_USER/DB_PASSWORD` trong `.env`. Config từ chối root hoặc mật khẩu trống. Không thay đổi quyền Java/game server.
- **Phiên/tài khoản:** isLogin kiểm tra lại ID, username và trạng thái ban; admin xác định bằng ID phiên đã ký. Cookie HttpOnly/SameSite/Path, bật Secure qua HTTPS. Trang công khai không còn dùng cookie username giả để tải thông tin tài khoản. Login trả thông báo chung và giới hạn thử; đăng ký giới hạn tần suất, kiểm tra kiểu/độ dài và xử lý username trùng.
- **Traversal:** `/spin-combo` chỉ nhận mã theo whitelist, resolve path trong thư mục combo và dùng đọc JSON bất đồng bộ.
- **Webhook:** xác thực Authorization chính xác và fail-closed nếu thiếu token; kiểm tra payload, mã giao dịch, số tiền nguyên dương có giới hạn; khóa hàng account trong transaction trước khi tính thưởng lần đầu, rồi ghi transfer và số dư atomically. Trùng mã theo UNIQUE được xử lý idempotently.
- **CSRF:** mọi POST/PUT/PATCH/DELETE kiểm tra Origin/Referer; webhook được miễn vì xác thực token riêng. Đã chuyển kích hoạt thành POST và đăng xuất thành POST. Cần đặt `TRUST_PROXY=1` khi TLS kết thúc sau proxy được kiểm soát, hoặc cấu hình PUBLIC_ORIGIN khi origin bên ngoài khác origin Node.
- **Payload/admin:** JSON/form body giới hạn 32 KB và 200 tham số; login/register/admin kiểm tra kiểu và giới hạn số dư; xóa player/account cùng transaction. Vòng quay lấy mẫu trọng số bằng crypto thay cho mảng theo ratio, kiểm tra cấu hình reward và giới hạn 20 yêu cầu/phút.
- **XSS:** tên/ảnh thưởng vòng quay được escape và URL ảnh giới hạn ở asset nội bộ; JSON danh sách template trong trang boss escape dấu `<`.
- **Headers/độ bền:** thêm nosniff, frame deny, referrer/permissions policy và HSTS trên HTTPS; gỡ public static `/node_modules`; giới hạn hàng đợi DB; route loader bắt lỗi async; tiến trình thoát khi uncaught exception để supervisor khởi động lại.
- **Dependency:** gỡ express-minify-html/html-minifier (không có bản vá phù hợp và có ReDoS), gỡ builder EJS cũ kéo theo phiên bản EJS lỗi thời cùng các dependency build không dùng. Nâng dependency qua `npm audit fix`. `npm audit --omit=dev` hiện báo 0 lỗ hổng; toàn bộ `npm audit` cũng báo 0.

## Cần xử lý tiếp

- Web và Java hiện dùng mật khẩu dạng rõ trong database. Chưa đổi sang hash vì Java xác thực cùng cột; đổi riêng web sẽ khóa người chơi khỏi game. Cần thiết kế migration phối hợp server Java và cơ chế nâng cấp mật khẩu cũ.
- Tài khoản DB riêng và khóa JWT mới được tạo trong `.env` cục bộ. Cần áp dụng cùng nguyên tắc trên máy chạy web thật, dùng secret riêng tại máy đó và cập nhật token webhook ở nhà cung cấp nếu luân chuyển. Không đưa `.env` vào source control.
- Cần đặt `PUBLIC_ORIGIN` hoặc `TRUST_PROXY=1` đúng topology HTTPS trước khi chạy sau reverse proxy. Khi chưa cấu hình, cookie Secure dựa trên HTTPS Node nhận trực tiếp và kiểm tra Origin dựa trên protocol Node.
- `npm audit fix` cập nhật `package-lock.json`. Repo có `yarn.lock` cũ; cần đồng bộ nếu deploy bằng Yarn. Pipeline webpack cũ bị bỏ khỏi npm scripts vì config tham chiếu builder không được khởi tạo.
- Database đã kiểm tra trước đó chưa có bảng `jackpot_pool`; migration Jackpot cần chạy riêng trên đúng DB trước khi dùng tính năng.
- Web cục bộ đã được restart qua supervisor `start_web.ps1`; log xác nhận các route được nạp và kết nối MySQL thành công. Endpoint `/health` trả trạng thái sau restart. Chưa kiểm thử trình duyệt hay payment thật. Không có migration schema giao dịch nào được chạy.
